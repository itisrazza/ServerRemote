# ServerRemote — agent guide

Read [README.md](README.md) (build, layout, translations, credits) and
[docs/architecture.md](docs/architecture.md) (connectors, sessions,
capabilities) first. This file covers what those don't: how to check work and
the conventions and traps in the GUI code.

## Checks

CI runs exactly these; run them before calling anything done:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

### Seeing the UI without a screen

Never screen-capture. Render the app headlessly instead:

```sh
SNAPSHOT_DIR=<scratch dir> cargo test -p server-remote render_review_snapshots -- --ignored
```

`render_review_snapshots` in `apps/server-remote/src/main.rs` drives the app
through a list of named states (menus open, dialogs, Settings sections, light
theme, Romanian) and writes `<name>-wgpu.png` at 2× scale. Add a state there
for any UI you change. Figma mockups arrive as 2× PNGs: compare by measuring
edges and colours in both images with Pillow (in a scratch venv), not by eye.
`settings-about-mockup` renders at the mockup's own 800×292 frame.

Raster images (`image` widget) decode on a worker thread, so they're missing
from the first rendered frame; that's expected, not a bug.

## GUI conventions (`apps/server-remote`)

- **Colours** come only from the theme's palette roles — see the role list
  above `extended_palette` in `src/ui/style.rs`. There's a dark and a light
  theme (`Appearance` setting, follows the OS by default), so a hard-coded
  colour will be wrong in one of them. Add a style function to `style.rs`
  instead.
- **Text** goes through `fl!("message-id")` (`src/i18n.rs`). Add every new
  message to both `i18n/en/server-remote.ftl` and `i18n/ro/server-remote.ftl`;
  `fl!` fails the build for IDs missing from English, and a test fails if the
  two files' IDs differ. Labels are therefore `String`, not `&'static str`.
  Product, protocol and format names stay literal. Connector-supplied labels
  (from `server-remote-core` capabilities) aren't translated yet.
- **Root wrappers:** `Application::view` wraps everything in `ui::pixel_snap`
  (rounds every layout edge to physical pixels for crisp low-DPI rendering)
  and `ui::arrow_cursor`. Both must stay at the root, outermost.
- **Sizes:** body text is 13px (`style::TEXT_SIZE`), controls 28px
  (`style::CONTROL_HEIGHT`), gaps 4px (`style::SPACING`). To share a baseline
  between text sizes, use `style::baseline`.
- **Fonts** are static instances of Nunito Sans generated by
  `scripts/instance-fonts.py`; iced can't set variation axes, so a new
  weight/width means a new instance there, not a runtime setting.
- **Settings** rows go through `setting(label, description, control)` in
  `src/ui/settings.rs`; persisted fields live in `persistence/settings.rs`
  and need `#[serde(default)]`-compatible defaults.
- **Icons:** add Carbon SVGs to `lib/icons/assets/` (16×16, `fill="white"`)
  and list them in `lib/icons/src/lib.rs`. An `Svg` ignores the surrounding
  text colour, so tint it explicitly (`ui::themed_icon`), or it renders black.
- **Contributors** on the About page come from
  `apps/server-remote/assets/contributors/generated.rs`, written by
  `scripts/fetch-contributors.py`. Rerun the script; don't edit the file.

## iced 0.14 traps

Read the iced source in `~/.cargo/registry/src/*/iced_*-0.14.*` rather than
trusting memory or docs; several behaviours below were only found there.

- `image::Handle::from_rgba` gets a fresh ID per call, so iced re-uploads it
  every frame. The remote display (`ui/kvm_display.rs`) uses a persistent
  `wgpu` texture via a hand-written `Widget`; keep it that way.
- `widget::shader::Shader` can't take keyboard focus (no `operation()` hook),
  which is why `KvmDisplay` is a raw `Widget`.
- The renderer's default text size is fixed at startup; it can't vary per
  window or scale factor.
- Dropdown menus have a fixed width (`MENU_WIDTH` in `ui/menu.rs`), and long labels wrap
  and overlap the next item. Check translations in the menus.

## Protocol traps

- **SPICE:** `SPICE_MSGC_DISPLAY_INIT` is mandatory in practice: spice-server
  sends nothing on the display channel until it arrives, despite the spec
  calling it optional.
- **Async reads:** never put a multi-`.await` read (header then payload)
  directly in a `tokio::select!` branch. If another branch wins mid-read, the
  bytes already read are lost and framing desyncs. Give each socket a reader
  task that sends whole messages over an `mpsc` channel (`spawn_reader` in
  `lib/spice`).
- **Frames:** drain all queued draw messages before sending one coalesced
  `Frame`; sending a frame per draw makes the display strobe.
